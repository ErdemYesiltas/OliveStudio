# Pixi 3D Lab — stage 0

An editor-only technical spike, **not 3D scene authoring**. Open the installed editor's panel finder (Cmd/Ctrl K), search **3D Lab**, then **Start / rebuild**. Closing the panel disposes its isolated renderer. No scene/component/asset document is written.

- Exact `@pixi/3d@0.1.0` / `pixi.js@8.23.0`; lazy import before this renderer's `Application.init`.
- View3D + directional/ambient lights + primitive + two animated Model3D instances + clickable Pixi 2D HUD.
- Shared source lease; independent animation players; removing an instance preserves shared geometry/materials.
- `RuntimeSession` fixed updates and an unstarted, owned public Ticker drive animation (`autoUpdate:false`). Pause freezes simulation; Step advances 1/60s. Seek resets and re-simulates, bounded to 10s.
- WebGPU requires `indirect-first-instance`; a failed capability probe selects WebGL. Actual renderer and float render-target support are reported. Feature fallback is unit tested; it is not simulated GPU rendering.
- An original 2KB embedded GLB with a 2s translation clip is generated by `node scripts/fixtures/pixi3d-cube.mjs`. No model download, textures or external decoder.
- Local Application teardown preserves global Pixi resources. Late initialization is awaited; stale publications are suppressed; rebuild waits for disposal.
- Module lock is recognized as editor-only by HTML preflight. No 3D runtime is added to existing exports.

## Reproduce

From `rewrite/`:

```sh
pnpm exec vitest run modules/pixi3d-lab
pnpm --filter @rewrite/desktop exec vite --config pixi3d.vite.config.ts
# http://127.0.0.1:5192/pixi3d-lab.html
pnpm --filter @rewrite/desktop exec vite build --config pixi3d.vite.config.ts
pnpm --filter @rewrite/desktop exec vite preview --config pixi3d.vite.config.ts --host 127.0.0.1 --port 5193
# http://127.0.0.1:5193/pixi3d-lab.html
```

The standalone page has a CSP forbidding JavaScript eval, matching the desktop constraint. Build/package checks and UI tests are separate; successful compilation alone is not native verification. Package the canonical app with `pnpm package:mac` after it closes.

## Pinned compatibility shim

Pixi 8.23's `pixi.js/unsafe-eval` entry is a **no-eval polyfill**, despite its name. Its fixed handler arrays do not cover the matrix/vector/color object parsers appended by 3D 0.1. This produces `functionMap[i] is not a function` on actual draw. `src/csp.ts` converts those values to standard array uniforms for this renderer, retaining Pixi's existing no-eval upload functions, matrix padding and live object updates. Existing 2D object parsers remain untouched. No CSP relaxation, dependency patch or global prototype override.

The shim uses version-sensitive `_generateUniformsSync` / `_generateUboSync` hooks (the same hooks Pixi's polyfill overrides). This is an explicit **beta adapter risk**, not a new public editor contract. Revalidate on either upstream version change; seek upstream support and remove the shim when available. Unit tests use real GlUniformGroupSystem, GlUboSystem and GpuUboSystem with mock GL upload calls.

## Limits / next gate

No Transform3D document schema, authoring camera/gizmos, model Library importer, 3D physics, 3D particles, MCP authoring tools or 3D game export yet. No compressed/skinned/large model compatibility or GPU-memory soak benchmark is claimed. The beta must remain behind its adapter. Next: spatial definitions in Scene without coupling SDK/kernel to Pixi, with old 2D document/undo/reparent/export regressions.
